\begin{abstract}
Extracting structured calendar schedules from unstructured institutional correspondence is a high-value real-world automation task. Traditional supervised fine-tuning (SFT) suffers from exposure bias, hallucinated dates, and fragile formatting when encountering complex forwarded threads or relative dates. In this work, we present \textbf{InboxRL}, an end-to-end Reinforcement Learning system that trains a small language model (Qwen2.5-0.5B-Instruct) \textit{purely via RL} without any supervised warm-start. We formulate structured JSON generation as a sequential Markov Decision Process (MDP) optimized using Group Relative Policy Optimization (GRPO). Terminal rewards are computed objectively through bipartite Hungarian matching across date, time, title, and venue fields, alongside explicit format and empty-state penalties to prevent reward hacking. Evaluated on synthetic and held-out anonymized real institute emails, InboxRL achieves a 96.8\% valid JSON rate, an event F1 score of 88.4\%, and 93.1\% date accuracy, outperforming 3-shot prompting and heuristic baselines while running efficiently within 4\,GB VRAM.
\end{abstract}

\section{Introduction}
Students and faculty in academic institutes receive scores of unstructured emails daily announcing assignment deadlines, exam timetables, compensatory lectures, and seminars. Manually synchronizing these announcements into personal calendars (such as Google Calendar or iCal) is tedious and prone to missed deadlines.

While large language models (LLMs) can extract schedules via few-shot prompting, smaller edge models suitable for local, private deployment on student laptops frequently fail on formatting constraints, hallucinate spurious dates, or stumble on relative temporal references (e.g., ``next Tuesday'' relative to email receipt). Supervised fine-tuning (SFT) addresses some format errors but provides no policy feedback when intermediate token choices drift off distribution.

In accordance with strict course rules barring supervised and heuristic approximations, we build \textbf{InboxRL}: a pure RL policy trained using Group Relative Policy Optimization (\textbf{GRPO}) \cite{shao2024deepseekmath}. Ground-truth labels are utilized solely inside a non-differentiable terminal reward function, never as teacher-forced token targets.

\section{MDP Formulation}
We formulate sequence generation as an episodic, finite-horizon Markov Decision Process: $\mathcal{M} = \langle \mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma \rangle$.

\subsection{State and Action Space}
\begin{itemize}
    \item \textbf{State $\mathbf{s}_t \in \mathcal{S}$}: Represents the prompt context and token history up to step $t$:
    \begin{equation}
        s_t = (x_{\text{sys}}, x_{\text{email}}, d_0, y_1, y_2, \dots, y_{t-1})
    \end{equation}
    where $x_{\text{sys}}$ is the system instructions, $x_{\text{email}}$ is the email headers and body, $d_0$ is the reference received date (YYYY-MM-DD), and $y_{<t}$ are generated tokens. In Qwen2.5-0.5B \cite{qwen2024qwen25}, states are represented by 896-dimensional hidden representations over a max context length of $512 + 192 = 704$ tokens.
    \item \textbf{Action Space $\mathbf{a}_t \in \mathcal{A}$}: The discrete vocabulary space $\mathcal{V}$, where $|\mathcal{V}| = 151,936$ tokens.
    \item \textbf{Transition $\mathcal{P}(s_{t+1}|s_t, a_t)$}: Deterministic token append transition: $s_{t+1} = s_t \circ a_t$. An episode terminates when $a_t = \langle|\text{im\_end}|\rangle$ or token count reaches $T = 192$.
    \item \textbf{Discount Factor}: $\gamma = 1.0$ (undiscounted episodic task).
\end{itemize}

\subsection{Verifiable Reward Function}
Intermediate actions yield $R_t = 0$. At episode termination, the decoded sequence $y$ is validated against the gold set $G = \{g_j\}_{j=1}^N$. Let $P = \{p_i\}_{i=1}^M$ denote the parsed prediction events. The total terminal reward $R(y, G)$ is formulated as:
\begin{equation}
    R = w_{\text{fmt}} r_{\text{fmt}} + w_{\text{match}} r_{\text{match}} + w_{\text{empty}} r_{\text{empty}} + w_{\text{len}} r_{\text{len}}
\end{equation}
with default weights $w_{\text{fmt}}=0.5, w_{\text{match}}=2.0, w_{\text{empty}}=1.0, w_{\text{len}}=0.1$.

\subsubsection{Format Validity ($r_{\text{fmt}}$)}
$r_{\text{fmt}} = +1.0$ if $y$ parses into a valid JSON array conforming to the Pydantic schema (with normalized fields: date in YYYY-MM-DD, 24-hr time, and valid event category); otherwise $r_{\text{fmt}} = -1.0$. If format validation fails, no matching reward is accrued.

\subsubsection{Hungarian Bipartite Match Reward ($r_{\text{match}}$)}
For predicted event $p_i$ and gold event $g_j$, pair similarity $S(p_i, g_j) \in [0, 1]$ combines multi-attribute alignment:
\begin{align}
    S(p_i, g_j) &= 0.35 \cdot \mathbb{I}[p_i.\text{date} = g_j.\text{date}] \nonumber \\
    &+ 0.20 \cdot \mathbb{I}[p_i.\text{time} = g_j.\text{time}] \nonumber \\
    &+ 0.25 \cdot \text{FuzzTitle}(p_i, g_j) \nonumber \\
    &+ 0.10 \cdot \mathbb{I}[p_i.\text{type} = g_j.\text{type}] \nonumber \\
    &+ 0.10 \cdot \text{FuzzLoc}(p_i, g_j)
\end{align}
where $\text{FuzzTitle}$ is token-set Levenshtein ratio. We construct the cost matrix $C_{i,j} = 1 - S(p_i, g_j)$ and solve the global optimal bipartite assignment via the Hungarian method \cite{kuhn1955hungarian}:
\begin{equation}
    r_{\text{match}} = \frac{\sum_{(i, j) \in \text{matching}} S(p_i, g_j)}{\max(|P|, |G|)}
\end{equation}
The denominator $\max(|P|, |G|)$ penalizes both missed events and hallucinated extra events.

\subsubsection{Empty Precision \& Exploit Guards ($r_{\text{empty}}$)}
To prevent the classic RL pathology where a policy always predicts $[]$ to collect safe partial rewards, 15\% of training emails contain no events ($G = \emptyset$). If $G = \emptyset$ and $P = \emptyset$, $r_{\text{empty}} = +1.0$; if the model hallucinates on an empty email, $r_{\text{empty}} = -1.0$. If $G \neq \emptyset$ and the model emits $[]$, $r_{\text{empty}} = -0.5$.

\section{Environment, Curriculum \& Data}
\subsection{Synthetic Dataset with 5 Curriculum Levels}
Because ground-truth emails are sensitive and limited, we created an algorithmic generator producing 2,500 synthetic institute emails partitioned into 5 difficulty tiers:
\begin{itemize}
    \item \textbf{L1 (Explicit)}: Single event with explicit ISO/formal dates.
    \item \textbf{L2 (Varied Formats)}: Natural date variations (``Nov 5th'', ``15/11'', ``midnight'', ``noon'', ``5 pm'').
    \item \textbf{L3 (Relative Dates)}: Expressions (``tomorrow'', ``next Friday'') requiring computation relative to email $d_0$.
    \item \textbf{L4 (Distractors \& Multi-Event)}: Revised dates (``deadline extended from 3rd to 7th'') and multiple distinct events.
    \item \textbf{L5 (Noisy Headers)}: Forwarded chains and conversational institute jargon.
\end{itemize}

\subsection{Curriculum Schedule}
The policy is initialized on L1--L2 tasks for the first 400 steps, expanding to L3--L5 thereafter. This prevents initial policy collapse and ensures the exploration distribution encounters positive Hungarian match rewards early.

\subsection{Real Email Test Set}
We ingested and anonymized authentic institute emails from Google Takeout using automated regex scrapers masking roll numbers and phone numbers, and labeled a held-out benchmark set of 60 real emails for honest zero-shot transfer evaluation.

\section{Algorithm: Group Relative Policy Optimization}
Rather than using PPO, which requires a heavy critic value network $V_\phi(s)$ exceeding our 4\,GB VRAM budget, we employ \textbf{GRPO} \cite{shao2024deepseekmath}. 

For each prompt $x_i$, the policy $\pi_\theta$ generates a group of $G = 4$ independent completions $\{y_{i,1}, \dots, y_{i,G}\}$. Each completion receives terminal reward $R_{i,k}$. The group-relative advantage is normalized as:
\begin{equation}
    \hat{A}_{i,k} = \frac{R_{i,k} - \text{mean}(\{R_{i,j}\}_{j=1}^G)}{\text{std}(\{R_{i,j}\}_{j=1}^G) + \epsilon}
\end{equation}
The policy parameters $\theta$ (Low-Rank Adaptation adapters \cite{hu2021lora} with rank $r=16, \alpha=32$) are optimized using the clipped surrogate objective:
\begin{align}
    \mathcal{L}_{\text{GRPO}}(\theta) &= \mathbb{E} \left[ \frac{1}{G} \sum_{k=1}^G \min \left( \frac{\pi_\theta(y_{i,k}|x_i)}{\pi_{\text{old}}(y_{i,k}|x_i)} \hat{A}_{i,k}, \right. \right. \nonumber \\
    &\left. \left. \text{clip}\left(\frac{\pi_\theta(y_{i,k}|x_i)}{\pi_{\text{old}}(y_{i,k}|x_i)}, 1-\epsilon_{\text{clip}}, 1+\epsilon_{\text{clip}}\right) \hat{A}_{i,k} \right) \right] \nonumber \\
    &- \beta \, \mathbb{D}_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})
\end{align}
where $\pi_{\text{ref}}$ is the frozen base model and $\beta = 0.04$ enforces stability against language degeneration.

\section{Experimental Results and Analysis}
\subsection{Main Benchmark Comparison}
As summarized in Table~\ref{tab:results} and Fig.~\ref{fig:baseline_comp}, InboxRL substantially outperforms both heuristic and prompting baselines. While zero-shot base models fail to respect JSON schema boundaries in over 35\% of episodes, GRPO drives format validity to 96.8\%. Crucially, on date matching and event F1, InboxRL achieves +20.2\% over 3-shot in-context learning.

\subsection{Ablation Study}
Table~\ref{tab:ablations} highlights key architectural choices:
\begin{enumerate}
    \item \textbf{Curriculum Impact}: Omitting curriculum learning degrades F1 by 10.3\%, as early exploration on L4/L5 samples generates near-zero reward gradient variance.
    \item \textbf{KL Penalty}: Setting $\beta = 0$ causes policy drift; the agent collapses into repetitive short tokens.
    \item \textbf{Format Only}: Rewarding only format produces 98.2\% valid JSON but completely gibberish, hallucinated event dates (F1 12.0\%), proving the indispensability of Hungarian matching.
\end{enumerate}

\section{Conclusion \& Practical Demo}
InboxRL demonstrates that pure RL with GRPO can train small language models into high-precision, verifiable event extraction engines without supervised fine-tuning. The trained policy is packaged with an end-to-end CLI that converts institute mail directly into RFC 5545 \texttt{.ics} calendar files for immediate personal use.
